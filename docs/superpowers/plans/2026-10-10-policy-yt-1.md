# POLICY-YT-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`).

**Goal:** 정책 문서에 YouTube API 필수 문장(부록 A)을 넣고, 투표 계열 낱말(부록 B)을 지우고, 조항 링크 6개를 고치고, YouTube API 자료가 30일을 넘지 않게 하는 예약 함수를 만든다.

**Architecture:** 문서는 `content/{ko,en,es}/*.md` 글자만 바꾼다. 조항 링크는 `PolicyContent`의 제목 id를 "제목 앞 번호"로 만든다(번호 없는 제목은 지금 slug 그대로). 30일 갱신은 순수 판정 함수(`functions/src/core/apiDataRetention.ts`) + 매일 도는 예약 함수(`scheduleYouTubeDataRefresh`)로, 기존 `youtubeGateway.listVideos`·`youtubeQuota` 를 재사용한다.

**Tech Stack:** Next.js 14 · react-markdown · Vitest 4 · Playwright · Firebase Functions v2 scheduler.

**Spec:** `outputs/PROMPT_ClaudeCode_POLICY-YT-1_v1.0_2026-10-10.md` (부록 A·B = 대표 승인 문구, 한 글자도 바꾸지 않는다)

## Review Focus

5. 30일 경계: `apiRefreshedAt` 없음 + `cachedAt` 도 없음 → 바로 삭제 대상이어야 함.

**대표 결정 (2026-10-10):** 권장안 채택 — 새 매일 예약 함수가 `status: "ended"` 대회의 `contestants.media.embed.status` 와 `tournaments.videoAlert` 를 지운다(할당량 0). 대회가 다시 진행 중이 되면 월요일 재검사가 다시 채운다 — 테스트로 고정. videoId(#4·#5)는 남긴다(PR C절에 "videoId 보관 — 정책 문구에 명시 없음, 신청서에 공개"). `contestants.name`(#6)은 운영자 입력.

**§7 해당(결정 전 기록):** #2(와 #3)는 `video_search_cache` 밖에서 30일 넘게 남는 API 파생 자료다 → 구현 범위를 넓히지 않고 보고, 대표 결정 대기.
권장안: `scheduleEmbedRecheck` 의 대상을 "active 대회"에서 "`media.embed.status.checkedAt` 가 25일 넘은 모든 contestant"로 넓히지 **않고**, 새 예약 함수가 **끝난 대회의 `media.embed.status` · `tournaments.videoAlert` 를 지운다**(재생 판정은 진행 중 대회에만 쓸모가 있고, 다시 활성화되면 다음 월요일 크론이 새로 채움). 할당량 0, 화면 영향은 Lab 목록의 ⚠️ 배지가 끝난 대회에서 사라지는 것뿐.
