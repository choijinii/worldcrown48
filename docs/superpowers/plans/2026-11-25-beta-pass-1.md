# BETA-PASS-1 Implementation Plan

> 실행 방식: 코티오가 이 세션에서 직접(대표 "그대로 진행해 줘"). 단계는 `- [ ]`.

**Goal:** 런칭 전 커튼은 그대로 두고, 명단(Firestore `config/betaAllowlist`)에 있는 구글 계정으로 로그인한 브라우저만 서명된 쿠키 `wc48_beta` 로 커튼을 지나게 하고, 들어오는 문 `/beta` 를 만든다.

**Architecture:** 통과증 = `<uid>.<expMs>.<HMAC-SHA256 base64url>` — 만들기·검증은 Web Crypto 순수 함수(`lib/launch/betaPass.ts`), 함수 쪽은 같은 형식을 node:crypto 로 만든다(`functions/src/core/betaPassCore.ts`). middleware 는 async 가 되어 쿠키를 검증한다. `/beta` 는 클라이언트 화면 — 로그인되어 있으면 자동으로 `betaPass` 를 부른다.

**Spec:** `outputs/prompts/PROMPT_ClaudeCode_BETA-PASS-1_1차베타명단로그인통과·beta초대페이지_v1.0_2026-11-25.md` (대표 저장소의 원본 · 시안 `BETA-PASS-1_beta페이지_시안_Main.dc.html`)

## Global Constraints
- 쿠키 이름 `wc48_beta` · `Path=/; Max-Age=<만료까지 초>; SameSite=Lax; Secure`(https 일 때)
- 비밀 이름 `BETA_PASS_SECRET` (Firebase 함수 비밀 + Vercel env, 같은 값)
- 만료 = min(런칭 시각, 지금+14일). **코티오 판단:** 런칭 시각이 이미 지났으면(코드 기본값 11/26 0시가 낡음 — 런칭 12/10) 그 값은 버리고 지금+14일.
- 화면 글자는 한국어만, 시안·§3 문구 글자 그대로. raw hex 금지(토큰만). 메뉴바 없음. noindex · 사이트맵 제외. 배너 자리 없음.
- 익명 계정을 만들지 않는다(D-41). 로그인 = `signInWithGoogle("beta")`.
- 런칭 뒤 `/beta` → `/` 307.

## Review Focus
1. 쿠키 값에 점이 더 많거나 빈 칸 · base64url 아닌 글자 → 위조로 처리(던지지 않음). → Task 1 유닛
2. 비밀이 비어 있는 middleware(Vercel env 를 아직 안 넣음) → 어떤 쿠키도 통과 못 함. → Task 1 · 3
3. 대문자·공백이 섞인 명단 메일 → 소문자·trim 비교. → Task 2 유닛
4. 로그인된 채 `/beta` 재방문 → 자동 확인(버튼을 다시 누르지 않아도). → Task 5 E2E ②
5. 명단 밖 → [다른 계정으로 로그인] 은 로그아웃 후 ① 상태. → Task 5 E2E ③
