## §1. 핵심 결론 (v1.0 유지 + v2.0 추가)

1. **법 집행은 선택적이다** — 소송·제재는 거의 전부 "명백한 상업적 도용"(비공식 굿즈, 무단 화보집, 얼굴 광고)에 집중된다. (v1.0 유지)
2. **CC 라이선스는 저작권만 해결한다** — 초상권·퍼블리시티권은 별개로 남는다. (v1.0 유지)
3. **[v2.0 확정] WC48은 인터넷신문사업자 등록을 추진한다** — 이로써 v1.0 §4의 최대 약점("WC48은 보도 매체가 아니라 보도 예외를 쓸 수 없다")을 구조적으로 보완한다. 숨피 3층 스택 중 1층(보도 프레임·프레스킷 접근)을 획득하는 결정.
4. **[v2.0 핵심 주의] 언론사 지위는 "면책 카드"가 아니라 "리스크 완화 층"이다** — 저작권법 §28 인용 성립 여부는 등록증이 아니라 **사용 방식**(주종관계·분량·필연성·시장 대체성)으로 판단된다. §7.2 참조.

## §3. 숨피 3층 스택 (v1.0 유지 — 요약)

1층 낮은 리스크 소스(보도자료·공식 임베드·보도 프레임) / 2층 통지·삭제 신속 대응 / 3층 권리자의 고소 유인 부재(무료 홍보 공생). **v2.0의 의미: 등록으로 WC48도 1층을 갖게 된다. 2층(신고 채널)·3층(직접 영리화 금지)은 기존 계획 유지.**

## §4. WC48 경계선 원칙 (v1.0 유지)

- **특정 인물의 초상을 "직접 돈 버는 지점"(광고 크리에이티브, 유료 재화, 굿즈)에 두지 않는다.** 미디어 피벗 명세의 BM 제약(하트·투표권 판매 금지)과 동일 원칙 — 충돌 없음.
- 시드 콘텐츠 Level 1(CC)/Level 2(공식 SNS 수동승인)/Level 3(절대 금지) 정책 유지. 만 19세 미만 절대 금지.
- 프레스킷·보도자료 이미지의 이용허락은 **보도 맥락**(기사·뉴스 스니펫)이 원칙. 투표 카드 본체에 쓰는 것은 회색지대 → G-LEGAL-3 자문 시 함께 질의.

## §7. 미디어 피벗 (2026-07-21 신설)

### §7.1 확정 사항 (대표 확정, 2026-07-21)

**인터넷신문사업자 등록 추진** — 대구광역시청 등록, 1인 발행인·편집인 구조. 이것이 유일한 확정 사항이며, 이하 §7.3~7.4는 현재 방향(가변)이다.

등록으로 얻는 것 (현실적 기대치):
1. 소속사 보도자료·프레스킷에 대한 정당한 접근 자격 (묵시적 이용허락 — 숨피 1층)
2. 소속사 제휴·커뮤니케이션 명분 (합법 최대치 5전략 ④의 실행 기반)
3. AI-Report·뉴스 팩토리의 공신력과 법적 프레임
4. 저작권법 §26·§28 원용의 **전제 조건** 충족 (충분 조건 아님 — §7.2)

등록으로 얻지 못하는 것 (과신 금지):
1. 저작권 자동 면책 ✗ — 인용 성립은 사용 방식으로 판단
2. 퍼블리시티권 "원천 차단" ✗ — 보도 예외는 실제 보도물에 적용, 투표 서비스+광고 수익은 별개 판단. "완화 층"으로만 기재
3. YouTube 약관 위반 면책 ✗ — 약관은 사법(私法) 계약, 언론 지위와 무관

### §7.2 §28 인용의 4대 판단 기준 (판례 정리)

인용이 정당하려면: ① 보도·비평·교육·연구 목적 ② **주종관계** — 자기 저작물(기사)이 主, 인용물이 從 ③ 인용 분량의 필연성 (필요 최소한) ④ 원저작물의 시장 수요를 대체하지 않을 것.

**WC48 적용:** 뉴스 스니펫 기사 안에 짧은 인용 → 성립 가능성 있음. 48개 클립이 본체인 투표 그리드 → 주종관계 역전으로 성립 가능성 낮음. 이 격차가 G-LEGAL-3 자문의 핵심 질의 사항이다.

### §7.3 클립 파이프라인 — 대표 결정 및 이견 병기 (2026-07-21)

**대표 결정:** 백오피스 클립 파이프라인(운영자가 YouTube URL + 3초 타임스탬프 입력 → 서버가 구간 추출·크롭 → WebP/MP4로 자체 스토리지 호스팅) 방향 채택. 단 **G-LEGAL-3 게이트(2026-07-25 개정) 적용** — 한국저작권위원회 저작권상담센터 **무료** 자문 1회 완료 전 프로덕션 투입 금지 (유료 변호사 자문은 형편상 무리라는 대표 판단 반영 · 2026-07-25).

**아키텍처 원칙 (2026-07-25 추가):** 시스템은 "인터넷신문 등록 완료" 시점을 기준 상태로 설계한다. Contestant 미디어 소스는 **image | embed | clip 3종 스왑 구조** — 등록 완료일에 클립 없이도(프레스킷 이미지 + 임베드 파사드) 시스템 100% 가동되며, 클립은 무료 자문 완료 즉시 끼워 넣는 업그레이드 모듈이다. 클립은 어떤 런칭 크리티컬 패스에도 놓지 않는다.

**Cowork 이견 (기록):** 위 방식은 복제권·전송권 침해 소지가 크고(§7.2 주종관계 요건 미충족 가능성), YouTube 약관 위반이며, "로고 제거" 처리는 분쟁 시 고의성 정황이 될 수 있다. 2026-07-13 합의(파일 복사 없는 공식 임베드 = 최강 카드)와 상충. 대안으로 **임베드 파사드**(정지 이미지 + hover 시 해당 카드만 YouTube iframe lazy-load, start 파라미터로 구간 지정, mute+autoplay)를 제시했고, 이는 동일 UX·동일 성능을 파일 복사 없이 달성한다. G-LEGAL-3 자문 결과가 부정적이면 임베드 파사드가 기본 대체안이다.

**자문 전 허용 범위:** 파이프라인 설계 문서·내부 기술 프로토타입(비공개, 소수 테스트 영상)까지. 프로덕션 배포·공개 서비스 노출은 금지.
