# 🚀 WorldCrown48 배포 가이드 (초보자용 · v1.0)

> Vercel 호스팅 + 도메인 연결(Cloudflare) + 자동 배포까지, 처음부터 끝까지.
> 작성일: 2026-06-09 · 대상: 코딩 입문 1인 개발자

## 0. 한눈에 보는 큰 그림

```
[내 컴퓨터] → git push → [GitHub] → 자동감지 → [Vercel 빌드·배포] → [라이브 사이트]
                                                                         ↑
                                              [Cloudflare DNS] 가 worldcrown48.com 을 Vercel로 안내
```

**핵심 한 줄:** 처음에 한 번만 연결해두면, 그 다음부터는 **"코드 저장 → git push"** 만 해도
사이트가 자동으로 새로 배포돼요. 손으로 파일을 서버에 올리는 작업이 아예 없어집니다.

### 등장 인물 3명

| 이름 | 쉬운 설명 | 비유 |
|------|-----------|------|
| **GitHub** | 코드를 보관하는 온라인 저장소 (이미 보유: `choijinii/worldcrown48`) | 원고 보관 창고 |
| **Vercel** | 코드를 받아 웹사이트로 만들어 인터넷에 띄워주는 호스팅(서버 운영) 회사 | 인쇄·배본소 |
| **Cloudflare** | `worldcrown48.com` 주소(도메인)의 길 안내(DNS)를 담당 | 우체국 주소록 |

> **용어:** **DNS**(Domain Name System) = 사람이 읽는 주소(worldcrown48.com)를
> 컴퓨터가 아는 위치로 바꿔주는 "인터넷 전화번호부"예요.

## 2. STEP 1 — 새로 만든 앱 코드를 GitHub에 올리기

제가 방금 레포에 아래 파일들을 만들어 두었어요. 이게 "배포할 실체"입니다.

```
worldcrown48/
├── package.json        ← 앱 정보·필요한 부품 목록
├── next.config.mjs     ← Next.js 설정
├── tsconfig.json       ← 타입스크립트 설정
└── app/
    ├── layout.tsx      ← 모든 페이지 공통 뼈대
    ├── page.tsx        ← "준비중" 화면
    └── globals.css     ← 색·폰트 스타일
```

### 2-1. 어느 브랜치에 올릴까?

Vercel은 보통 **`main` 브랜치**에 올라온 코드를 "진짜 라이브(Production)"로 배포해요.
지금 작업 브랜치가 `main`이 아니라면, 이 앱 코드를 **`main`에 합쳐야** worldcrown48.com에 나옵니다.

> **브랜치(branch)** = 코드의 작업 갈래. `main` = 공개되는 최종본 갈래.

### 2-2. 명령어 (터미널에서)

```bash
# 1) 현재 위치·상태 확인
cd ~/Projects/worldcrown48
git status

# 2) main 브랜치로 이동 (작업 내용 합치기 전)
git checkout main

# 3) 방금 만든 앱 파일들을 main 으로 가져오기
#    (지금 파일이 다른 브랜치에 있다면 그 브랜치명을 넣으세요)
git merge feat/choijinii-patch-1   # 예시 — 실제 브랜치명으로 교체

# 4) GitHub에 올리기
git push origin main
```

> 💡 어느 브랜치에 파일이 있는지 헷갈리면, 이 부분은 **Claude Code에게**
> "방금 만든 Next.js 준비중 페이지를 main 브랜치에 올려줘" 라고 맡기는 게 가장 안전해요.
> (브랜치 작업은 한 글자 실수가 꼬임을 만들기 쉬운 부분이라, 코드 담당 에이전트가 적합합니다.)

## 3. STEP 2 — Vercel 가입 (GitHub 계정으로)

1. https://vercel.com 접속 → 오른쪽 위 **Sign Up** 클릭
2. **"Continue with GitHub"** 선택 → GitHub로 로그인
   - 이렇게 하면 GitHub ↔ Vercel 이 자동으로 연결돼서, 다음 단계가 훨씬 쉬워져요.
3. 가입 중 **계정 종류**를 물으면 일단 **Hobby (개인/무료)** 선택
   - ⚠️ 상업용 요금 주의사항은 아래 **8번**에서 자세히 설명드려요. 지금은 Hobby로 시작 OK.
4. GitHub이 "Vercel에게 어떤 저장소 접근을 허용할지" 물으면,
   - **All repositories(전체)** 또는 **Only select repositories → `worldcrown48`만 선택** 둘 다 가능.
   - 보안상 **선택 저장소만 허용**을 추천해요.

---

## 4. STEP 3 — 프로젝트 불러오기 & 첫 배포

1. Vercel 대시보드 → **Add New… → Project** 클릭
2. 목록에서 **`choijinii/worldcrown48`** 옆 **Import** 클릭
3. 설정 화면이 나오면 — **대부분 그대로 두세요.** Vercel이 Next.js를 자동 인식합니다.

| 항목 | 값 | 설명 |
|------|-----|------|
| Framework Preset | **Next.js** (자동) | 손댈 필요 없음 |
| Root Directory | `./` (기본) | 앱이 레포 최상위에 있으니 그대로 |
| Build Command | 자동 (`next build`) | 그대로 |
| Environment Variables | **지금은 비워둠** | Firebase 키 등은 나중에 (→ 9번) |

4. **Deploy** 클릭 → 1~2분 기다리면 빌드(코드를 사이트로 변환) 완료 🎉
5. 완료되면 **`worldcrown48-xxxx.vercel.app`** 같은 임시 주소가 나와요. 클릭해서 "준비중" 화면이 뜨면 성공!

> 이 임시 `.vercel.app` 주소는 **도메인 연결 전에도 항상 작동**해요.
> 즉, 도메인 설정이 막혀도 사이트 자체는 이미 인터넷에 살아있는 거예요. 안심하세요.

## 5. STEP 4 — 도메인(worldcrown48.com) 연결

여기가 유일하게 손이 좀 가는 부분이에요. 천천히 따라오시면 됩니다.

### 5-1. Vercel 쪽: 도메인 추가

1. Vercel 프로젝트 → 상단 **Settings → Domains**
2. 입력칸에 **`worldcrown48.com`** 입력 → **Add**
3. Vercel이 **"이 DNS 레코드를 추가하세요"** 하고 값을 보여줘요. 그 값을 메모해두세요.
   보통 아래와 같습니다 (Vercel 화면에 표시된 값이 우선):

| 종류 | 이름(Name) | 값(Value) |
|------|-----------|-----------|
| **A** | `@` (= worldcrown48.com) | `76.76.21.21` |
| **CNAME** | `www` | `cname.vercel-dns.com` |

### 5-2. Cloudflare 쪽: DNS 레코드 입력

1. https://dash.cloudflare.com 로그인 → **worldcrown48.com** 선택
2. 왼쪽 메뉴 **DNS → Records**
3. 기존에 같은 이름(`@`, `www`)의 A/CNAME 레코드가 있으면 **삭제 또는 수정**
4. **Add record** 로 위 표의 값 그대로 추가
5. ⚠️ **가장 중요 — 프록시 끄기:** 각 레코드의 **Proxy status** 를
   **회색 구름(DNS only)** 으로 설정하세요. 주황 구름(Proxied)이면 Vercel과 충돌나
   인증서 오류(사이트 안 열림)가 생길 수 있어요.

```
   주황 구름 🟠 Proxied     ← ❌ (충돌 위험)
   회색 구름 ⚪ DNS only    ← ✅ (이걸로!)
```

### 5-3. 기다리기

- 보통 **수 분~수십 분**이면 연결돼요. 길면 최대 24~48시간(드물게).
- Vercel Domains 화면에 **Valid Configuration ✅** 초록불이 뜨면 끝.
- 이제 **worldcrown48.com** 으로 접속하면 "준비중" 화면이 떠요!

> **이메일 걱정:** 이전에 설정한 Cloudflare 이메일 전달(MX 레코드)은 **건드리지 않으면 그대로 유지**돼요.
> 위에서 추가하는 건 A/CNAME(웹 주소)뿐이라 메일 수신에 영향 없습니다.

## 6. STEP 5 — 자동 배포 확인 (이게 핵심 보상!)

이제 진짜 마법을 확인할 차례예요.

1. 코드를 아무거나 한 줄 고쳐요 (예: `app/page.tsx` 의 "COMING SOON" → "COMING SOON ✦")
2. 저장 → `git push origin main`
3. **아무것도 더 안 해도** Vercel이 자동으로 감지해서 새로 빌드·배포해요.
4. 1~2분 뒤 worldcrown48.com 새로고침 → 바뀐 내용 반영 완료 ✨

### Preview(미리보기) 배포 — 1인 개발자의 안전망

`main`이 아닌 **다른 브랜치**에 push하면, Vercel이 **별도 미리보기 주소**를 자동 생성해요.
- 실제 사이트(worldcrown48.com)는 그대로 두고,
- 새 기능을 임시 주소에서 먼저 확인 → 괜찮으면 `main`에 합치기.
- 혼자 일해도 "실수로 라이브를 망가뜨리는" 위험을 줄여줘요. 적극 활용 추천!

- **정식 런칭·수익화 시점:** Pro로 전환. 월 $20은 1인 서비스 인프라 비용으로 합리적이에요.

## 9. 🔒 환경 변수(Environment Variables) — 보안 주의

나중에 Firebase, Claude API 키 등을 연결할 때는 **코드에 직접 키를 쓰면 안 돼요.**
대신 Vercel **Settings → Environment Variables** 에 비밀값으로 넣습니다.

- 키는 절대 GitHub에 커밋하지 마세요. (그래서 `.gitignore`에 `.env*`를 넣어뒀어요.)
- **키 값은 채팅·스크린샷으로 공유하지 마세요.** 특히 Claude API 키는 유출 시 과금 위험이 커요.
- 이 부분은 실제 연결할 때 단계별로 다시 안내해 드릴게요.

## 10. 🆘 자주 나는 문제 (Troubleshooting)

| 증상 | 원인 | 해결 |
|------|------|------|
| 배포는 됐는데 도메인이 안 열림 | DNS 전파 대기 중 | 10~30분 기다리기 |
| 사이트 인증서/보안 오류 | Cloudflare 프록시가 켜져 있음 | 회색 구름(DNS only)로 변경 |
| Vercel Domains에 빨간불 | DNS 값 오타 | A=`76.76.21.21`, CNAME=`cname.vercel-dns.com` 재확인 |
| 빌드 실패(Build Error) | 코드 오류 | Vercel 로그(빨간 줄) 복사 → Claude Code에 붙여넣기 |
| 푸시했는데 사이트 안 바뀜 | main이 아닌 브랜치에 push함 | `main`에 합쳤는지 확인 |

## 11. 🎯 런칭·마케팅 연계 (1인 기획자 관점)

"준비중" 페이지는 그냥 대기 화면이 아니라 **첫 마케팅 자산**이 될 수 있어요.

- **이메일/관심 등록 받기:** "출시 알림 받기" 입력칸을 추가하면, 런칭 전부터 잠재 사용자 명단을 모을 수 있어요. (다음 단계에서 간단히 붙일 수 있음 — 무료 도구: Google Form, Tally, Formspree 등)
- **SNS 공유 미리보기:** `layout.tsx`에 OpenGraph 정보를 넣어뒀어요. 링크를 인스타·X 등에 공유하면 제목·설명이 예쁘게 떠요. 런칭 카운트다운 게시물에 활용하기 좋아요.
- **검색 노출(SEO) 씨앗:** 도메인이 일찍 살아있으면 검색엔진이 미리 인지해, 런칭 시 노출에 유리해요.
- **현실 조언:** 준비중 페이지는 **3~4시간이면 "알림 받기"까지 완성** 가능. 비용 0원. 혼자 충분히 할 수 있는 범위예요.
