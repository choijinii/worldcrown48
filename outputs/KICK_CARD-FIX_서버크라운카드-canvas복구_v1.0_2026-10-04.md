## 2. 팬에게 미치는 영향

- 완주 직후 보이는 카드: 브라우저가 직접 그리므로 **보인다.**
- 서버 카드가 없으므로: 완주 화면의 **"이전 참여의 Crown Card" 목록**(RUN-1 "지난 판의 카드는 전부 보존")이 비어 보일 것이다. 그 밖에 `crown_cards`·Storage PNG를 쓰는 곳(공유 미리보기 그림 등)은 Claude Code가 Phase 0에서 목록으로 정리한다.
- 크라운 카드는 공유 → 유입 → 가입의 중심이고, 런칭 순서 마지막의 "크라운 카드 새 디자인"도 이 서버 카드 위에 올라간다.

## 3. 무엇을 한다 (범위 IN)

1. **원인 확정** — Node 22에서 canvas 2.x가 설치되지 않는다는 것을 증거로 확인(설치 로그·버전 지원표).
2. **고친다** — Node 22에서 확실히 설치되는 그림 부품으로 바꾼다. 후보: canvas 3.x 또는 @napi-rs/canvas(미리 만든 설치 파일을 쓰는 부품). 어느 쪽이든 그림 결과(1200×630 PNG, 지금 그림과 같은 모양)는 그대로.
3. **다시는 조용히 실패하지 않게** (23:37 대표 의견 반영 — 손이 덜 드는 방법) — ① 그림 부품을 **필수 설치(dependencies)**로 옮겨, 설치가 실패하면 배포 자체가 실패하게 한다(추가 비용 0). ② 실제 사이트에서 `render failed`가 찍히면 **대표 메일로 알림**(구글 클라우드 로그 기반 알림, 한 번 설정). ③ **운영자 페이지(Admin Dashboard) 알림 목록에도 표시**(23:46 대표 요청) — 이미 있는 알림 목록(`admin_alerts`, 지금은 차트 이상 징후만 씀)에 "크라운 카드 생성 실패" 종류를 추가한다. 같은 종류는 한 건으로 묶고 횟수만 올린다(알림 폭주 방지). ④ 카드가 정말 만들어지는지는 E2E-1의 게스트 시험(hf3 E2E-1)이 이미 확인하므로, **새 그림 시험은 만들지 않는다.**
4. **배포 후 확인** — 대표가 함수 하나(`onChampionConfirmed`)를 배포 → PR #114 시험을 다시 돌려 **hf3 5/5**(카드 문서 생성 확인) → 그 뒤 #114 병합.

## 4. 하지 않는다 (범위 OUT)

- CI에서 PNG를 직접 그려 보는 새 시험 — **만들지 않음(대표 23:37)**. 필수 설치 + 알림 + 기존 hf3 E2E-1로 충분.
- 다른 함수·클라이언트 화면 변경. 재시도 정책 변경(영구 실패 시 재시도하지 않는 원칙은 유지).
- E2E-1 시험의 "6번 중 1번 착지 실패" — CARD-FIX 뒤에도 남으면 따로 본다.
