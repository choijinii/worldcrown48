> 용어 풀이
> - **E2E**(End-to-End, 끝에서 끝까지) = 로봇 브라우저가 실제 화면을 처음부터 끝까지 눌러 보는 자동 시험.
> - **CI**(지속 통합) = PR을 올릴 때마다 GitHub가 자동으로 시험을 돌려 초록/빨강을 붙여 주는 장치. 그 안의 시험 묶음 하나를 **워크플로**(`.github/workflows/*.yml`)라고 부른다.
> - **타입 검사(tsc)** = 코드를 실행하지 않고 문법·자료형 오류를 미리 찾는 검사.

## 2. 무엇을 한다 (범위 IN)

1. **복구** — `hf3-guest-run.spec.ts`의 떨어진 조각을 정리해 문법 오류 0. 시험 5개(E2E-1·2·3·4·5)의 기대값이 **지금 확정 규칙**(참가 규칙 v2.1 · 원장 D-41)과 맞는지 하나씩 대조해 고친다.
2. **CI 연결** — 이 파일을 C-1 워크플로(`c1-e2e.yml`)의 E2E 명령에 추가한다(같은 비밀값 `TEST_UID`·`NEXT_PUBLIC_FIREBASE_API_KEY`·`PREVIEW_URL`을 이미 씀).
3. **타입 검사가 e2e/를 보게** — 별도 설정 파일(`tsconfig.e2e.json`) + 명령 `npm run typecheck:e2e` + CI 단계 추가. (본 `tsconfig.json`은 Vercel 빌드가 쓰므로 건드리지 않는다.)
4. **고아 방지 장치** — "e2e/ 의 모든 시험 파일은 어느 워크플로엔가 연결돼 있어야 한다"는 단위 시험 하나(vitest). 이 파일은 9/20에 고아인 것이 발견되고도 2주 넘게 그대로였다 — 사람이 기억하는 대신 기계가 막게 한다.
5. **실제로 돌았다는 증거** — 시험이 "건너뜀(skip)"이 아니라 "통과(pass)"했다는 숫자(통과 N · 건너뜀 0)를 보고서에 남긴다.
