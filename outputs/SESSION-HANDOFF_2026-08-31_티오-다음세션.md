## 이번 세션에서 있었던 혼란 (다음 세션이 반드시 피해야 할 것)

1. **실제 데이터를 먼저 확인하지 않고 "실제 대회 4개의 ID를 찾아야 한다"고 말했다.** 마케팅 문서(UTM_RULES_v1.0.md)에 있는 4개 대회 이름(best_stage_48 등)을 실제 서비스 데이터와 연결하려 했는데, **정작 라이브 사이트(worldcrown48.com)를 먼저 확인했다면 "지금 대회가 0개"라는 걸 바로 알 수 있었다.** 코드만 뒤지고 실제 서비스 상태를 안 본 채로 "대회 ID를 확인해야 한다"고 대표님께 되물어서 불필요한 왕복이 생겼다. → **다음 세션 원칙: 코드 변경을 제안하기 전에, 그 변경이 기대는 전제(대회가 존재하는지, 데이터가 있는지 등)를 먼저 실측(라이브 사이트·Firestore 등)으로 확인하고 나서 말할 것.**
2. ~~**대회가 실제로 없다는 걸 몰랐다.** 대표님은 아직 편집기에서 토너먼트를 생성한 적이 없다~~ **(08-31 정정: 테스트 대회 12개 이상 실재. 이 항목 자체가 잘못된 전제였음)** — 마케팅이 기획한 4개 대회(최고의 무대 48 / 현존 최고 퍼포먼스 아이돌 48 / 4세대 최고로 사랑받는 아이돌 48 / K-POP 커버 크리에이터 48)는 **아직 만들어지지 않은 계획 단계**다.
3. **"마케팅 슬러그 대응표를 채워달라"고 요청한 것 자체가 시기상조였다.** 대회가 없으니 채울 대상도 없다. 이 요청은 대표님이 실제로 대회를 만든 "이후"에나 의미가 있다.
4. **QR 삭제 작업 중 기존 테스트가 깨져서 테스트 파일을 고쳤는데, 이걸 "새 작업을 시킨 것처럼" 느껴지게 설명했다.** 실제로는 대표님이 지시한 "QR 삭제"의 필연적 결과였다(QR이 그려지는지 확인하던 기존 테스트가 QR을 지우면 당연히 깨진다) — 새로 지시받지 않은 일을 벌인 게 아니라, 이미 지시받은 변경의 뒷정리였다. 다만 **대표님께 "이건 왜 필요한지" 먼저 설명하지 않고 진행해서 오해가 생겼다.** → 다음 세션 원칙: 지시된 변경 때문에 다른 파일도 같이 고쳐야 하면, 고치기 전에 "이것 때문에 이것도 같이 고쳐야 해요"라고 먼저 짧게 알릴 것.
5. **테스트 실행을 대표님 숙제로 넘겼다.** 이 세션 환경(리눅스 샌드박스)이 대표님 맥용으로 설치된 node_modules(darwin 바이너리)를 그대로 마운트해서 쓰다 보니 `vitest` 자체가 실행이 안 됐다(환경 문제, 코드 문제 아님). 이걸 "대표님이 터미널에서 직접 돌려서 확인해주세요"로 넘겼는데, 요청하지 않은 부담을 지운 셈이 됐다.

**공통 원인: 확인 순서가 거꾸로였다.** "이럴 것이다 → 그러니 이것부터 알려달라"는 순서 대신, **"확인해보니 이렇다 → 그래서 이렇게 하면 된다"** 순서로 말할 것.
