## 0. 핵심 발견 3가지

1. **"Voter"는 화면 문구에는 의외로 거의 없다.** 코드 주석·변수명(안 보이는 곳)에 수백 번 나오지만, 사용자 눈에 보이는 곳은 아래 §2의 **6곳**뿐. 즉 "Voter → 팬" 화면 적용은 생각보다 작은 작업.
2. **UI 카피는 이미 "팬"을 쓰고 있다.** 히어로 문구 "오직 팬의 선택 · Global Fan Voting · pure fan choice" — 개정은 사실상 브랜드 보이스와 용어집을 **일치시키는 일**.
3. **가장 파급이 큰 노출은 뉴스 기사.** 기사 생성 지침(newsPrompts.ts)이 기사에 "Voter·Voter Count" 용어 사용을 지시 중 → **발행 기사(대외 공개물)에 Voter가 계속 실린다.** 인터넷신문 등록을 준비하는 지금, 우선 검토 대상.

| # | 위치 | 노출 문구 | 보는 사람 | 우선도 |

| 2 | UserAvatar (아바타) | 위와 동일한 기본값 **"Voter"** | 모든 로그인 사용자 | 높음 |

## 4. 권고 방식 — "표시 용어(Display Term)" 층 추가

LANGUAGE.md의 불변 규칙(RULE 1)과 충돌하지 않는 개정 방법:

```
[유지]  코드·DB·영문 공식명:  Voter, role:'voter', voterId …  ← 배관 (안 건드림)
[추가]  표시 용어 (ko/en/es):  팬 / Fan / Fan                ← 간판 (화면·기사에만 적용)
```

- LANGUAGE.md에 "표시 용어" 열을 추가하는 **개정판(버전 업 + 개정 이력)**으로 기록 — 정의를 바꾸는 게 아니라 표시 층을 더하는 것이므로 RULE 1 준수.
- 적용 PR 스코프 = §2의 6곳 + 기사 지침 1곳. 코드 식별자·DB 필드 변경 **금지**.
- 3언어 동시 확정 필수: 팬 / Fan / Fan (es도 Fan 통용, 결정 세션에서 확정).
