## §4 ADRs (2026-08-09 대표 확정 사항 — 재토의 금지)
- **ADR-EV-1**: 루프 길이 **10초**(3초 기각). 무음 고정.
- **ADR-EV-2**: **Most Replayed 자동 수집 금지**(공식 API 미제공 — 비공식 스크래핑 배제). 대체 = W2의 3층 추천 + 운영자 눈 확인([원본 열기]).
- **ADR-EV-3**: 카드 노출 조합 확정 — 크롭 + 클릭 차단(`pointer-events:none`) + `controls=0` + **클릭 가능한 출처 칩 "▶ YouTube"**(새 탭에서 원본). 출처 칩의 시각 디자인은 시안 트랙(이 킥에서는 기능 동작하는 미니멀 칩만).
- **ADR-EV-4**: 표면별 재생 정책 — 검수기 미리보기 = 활성 슬롯 1개만 라이브(나머지 썸네일). 동시 플레이어 상한 상수 `MAX_CONCURRENT_PLAYERS=6` 를 lib/embed에 정의(후속 킥 공용).
- **ADR-EV-5**: API 키는 서버 전용(Secrets). 클라이언트에서 YouTube Data API 직접 호출 금지.
- **ADR-EV-6 (2026-08-09 대표 확정)**: 검수기·슬롯·검증 배치는 **48 하드코딩 금지, 규모 N 파라미터 기반**으로 구현. 설정 상수 `BRACKET_SIZES = [48, 24, 12]`(단일 소스, 확장 가능 구조). **32강·16강은 런칭 후 로드맵** — 단, 이는 검수기가 아니라 브래킷 엔진의 결정 사항임: 48/24/12는 모두 6→3(결승 3인)에 도달하지만 32/16은 4→2에 도달해 THE FINAL 3인 구조와 맞지 않음. 32/16 도입 시 결승 구조(3인 유지 변형 vs 2인 결승) 별도 결정 필요. 검수기 쪽은 BRACKET_SIZES에 숫자만 추가하면 되도록 지금부터 대비한다.
- **ADR-EV-7 (2026-08-09 대표 확정)**: 검수기 **콘솔은 어드민 전용 비공개**. MVP2 Lab 유저 공개 시에는 같은 코어(검증 함수 + 추천 + LoopPlayer)를 재사용한 **단건 위젯**(링크 1개 → 자동 검증 → 킬링파트 추천 → 미리보기)을 토너먼트 생성 흐름에 내장(별도 소형 킥, 이 킥 스코프 아님). 코어는 이 재사용을 전제로 UI 비의존으로 설계할 것.

## §7 Testing Strategy
lib/embed 순수 유닛(파서·클러스터·정규화) + functions 유닛(fixture mock) + Playwright E2E(검수기 모달 흐름, spec 경로 스코프 [[feedback-workflow-spec-scope]]). 렌더 테스트 금지(§0.5). 에뮬레이터는 Java 21+ [[feedback-firebase-tools-java21]].

## §8 Edge Cases
- 48줄 미만/중복 링크/URL 아닌 줄 → 행 단위 오류 표시(전체 거부 아님)
- 댓글 비활성·0개 영상 / 라이브 스트림·Shorts / durationSec < startSec+10(짧은 영상 → end=duration)
- 쿼터 소진(403 quotaExceeded) → 사용자 메시지 + Auto-STOP 아님(재시도 안내)
- 임베드 허용인데 런타임 재생 실패(101/150) → 폴백 + videoStatus 마킹
