이미지 URL (라이선스 확인)
← 슬롯 카드 맨 아래의 "이미지 URL" 입력 칸이 이번 안건의 다른 한쪽입니다. 목업에서는 이 칸을 삭제하기로 했었지요.
2실측에서 드러난 두 가지 문제
문제 A — 이미지 URL 칸을 지우면 안 되는 상태였습니다.
킥 규칙대로 "지우기 전에 이 칸을 읽는 코드를 전부 찾아보라(grep)" 했더니 6곳에서 이 값을 읽고 있었습니다. 어디 6곳인지 상세 목록은 제가 아직 Claude Code에게 받지 않았는데(요청하면 바로 받을 수 있습니다), 예상되는 곳은 슬롯 미리보기·발행 문서·매치 화면 등입니다. 읽는 곳이 남아 있는 채로 데이터를 지우면 그 화면들이 깨질 수 있어, 안전장치(Auto-STOP)가 작동해 삭제를 멈춘 상태입니다.
문제 B — [🖼 이미지 생성] 버튼은 약속과 실제 능력이 다릅니다.
이게 "버튼 의미 붕괴"라고 보고된 문제의 정체입니다. 아래를 비교해 보세요.
버튼이 약속하는 것 (문구) "AI가 48명을 채우고 → 이미지 검수까지 자동으로 합니다" — 누르면 인물 사진이 채워질 것처럼 읽힙니다.
≠
실제로 하는 것 AI가 이름·국적 등 명단만 채웁니다. 이미지는 한 장도 가져오지 않습니다. 이미지 칸은 빈 채로 남고, 사람이 라이선스를 확인한 사진 주소를 직접 붙여넣어야 합니다.
왜 이미지를 자동으로 못 가져오나요? 실수가 아니라 우리가 처음부터 정한 저작권 원칙 때문입니다. 영상은 "유튜브 공식 플레이어로 보여주기(임베드)"라는 법적으로 안전한 길이 있어 자동화했지만, 이미지는 그런 안전한 길이 없습니다. 인터넷의 사진을 자동으로 긁어오면 저작권·초상권 침해가 되기 쉬워서, "이미지는 반드시 사람이 라이선스를 확인하고 넣는다"로 설계해 두었던 것입니다. 그래서 이 버튼은 태생적으로 '이미지 생성'이라는 이름을 다 지킬 수 없었고 — 목업 단계에서 제가 이 간극을 미리 짚어드리지 못했습니다. 그 점도 사과드립니다.
3선택지 4가지 — 각각 무엇이고, 무엇을 얻고 잃나
선택지무엇을 하는 것인가얻는 것잃는 것 / 대가
① 칸 유지
(F 축소)비용 0		 이미지 URL 칸과 데이터를 그대로 둡니다. "삭제" 계획만 접습니다. (읽는 곳 6곳이 있으니 지금 지우는 것은 어차피 위험) 아무것도 안 깨짐. 이미지 기반 토너먼트의 수동 경로 유지. 목업에서 정한 "칸 삭제 → 카드 축소"를 못 함. 카드가 한 줄 더 큼.
② 문구 정직화반나절 버튼은 그대로 두되, 이름과 설명을 실제 능력에 맞게 고칩니다. 예: "🖼 명단 채우기 — 이미지는 라이선스 확인 후 직접 입력". (우리 "버튼명은 하는 일 기준" 원칙의 적용) 운영자(대표님)가 버튼을 눌렀을 때 기대와 결과가 일치. 싸고 빠름. "이미지 생성"이라는 매력적인 이름을 잃음. 이미지는 여전히 수동.
③ 버튼 철회반나절 🖼 버튼을 아예 제거하고 [🎬 동영상 생성] 하나만 남깁니다. 이미지 토너먼트는 슬롯에서 손으로만. 화면이 가장 단순. 오해 소지 0. 대표님이 목업에서 승인한 2버튼 구조가 1버튼이 됨. 이미지 토너먼트 비전이 화면에서 사라짐.
④ 재정의
(이미지 소싱 파이프라인)별도 킥 규모		 버튼이 이름값을 하도록, 라이선스가 확인된 이미지를 자동으로 찾아오는 새 시스템을 만듭니다. 상세는 아래 ④절. 버튼 약속을 진짜로 이행. 이미지 토너먼트 제작이 영상만큼 쉬워짐. 큰 공사 + 법리 미확보(아래 참조). LAB-UX-1 안에서는 불가능, Arena 일정이 뒤로 밀림.
4"재정의(이미지 소싱 파이프라인)"는 왜 필요하고, 왜 신중해야 하나
왜 필요한가: [🖼 이미지 생성]이라는 버튼이 진짜로 이미지를 만들어 오려면 이 길뿐입니다. 만들려면 세 가지가 필요합니다 — ⓐ 라이선스 필터가 있는 이미지 검색(예: 상업적 이용이 허락된 이미지만 걸러 주는 검색 API — 외부 서비스 연동), ⓑ 검수 층(영상 검수기처럼 "이 사진이 정말 그 인물인가, 쓸 수 있는 라이선스인가" 판정), ⓒ 법리 확인.
왜 신중해야 하나 — 법리가 영상과 다릅니다. 우리의 영상 전략은 "유튜브 공식 플레이어로 보여주기(임베드)"라서 판례로 확인된 안전한 카드였습니다(법률 상담 08-08 확정). 그런데 이미지는 임베드 같은 보호 장치가 없습니다 — 사진을 우리 화면에 띄우는 것은 복제·전송 문제가 바로 걸리고, K-POP 인물 사진은 초상권까지 겹칩니다. "라이선스 확인된 이미지만"이라는 필터도 오탐(라이선스 표기가 틀린 이미지)이 있어서, 이 길을 가려면 다음 법률 상담에서 이미지 소싱의 안전선을 먼저 확인하는 것이 순서입니다. 즉 ④는 "하면 안 된다"가 아니라 "지금 이 킥에서 곁다리로 할 일이 아니라, 법리 확인을 앞세운 별도 킥감"이라는 뜻입니다.
5대표님께 여쭙는 것
선택지는 섞을 수 있습니다(예: ①+② / ①+②를 지금 하고 ④는 법률 상담 뒤 별도 킥으로 검토). 제 의견은 참고로만 말씀드리면 — 지금 킥에서는 ①+②(칸 유지 + 문구 정직화)로 정직하게 맞춰 두고, ④(재정의)는 "다음 법률 상담 확인 목록"에 올려 두었다가 상담 결과를 보고 별도 킥으로 판단하는 것이 품질과 법적 안전을 다 지키는 길이라고 봅니다. ③(철회)은 대표님이 승인하신 2버튼 구조를 되돌리는 것이라 권하지 않습니다.

다만 이것은 어디까지나 추천이고, 결정은 대표님 몫입니다. 원하시면 결정 전에 imageUrl을 읽는 6곳의 상세 목록을 Claude Code에게 받아 함께 검토할 수도 있습니다. 방향을 정해 주시면, 그때 실행 프롬프트를 만들어 드리겠습니다.
