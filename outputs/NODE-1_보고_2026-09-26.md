## Phase 4 — 눈검사 준비 (조사만, 실행 안 함)

### 4-1. 서비스 계정 키 없이 시드할 수 있나 → **지금 스크립트 그대로는 불가**
- `scripts/seed-chart-preview.mjs`는 `FIREBASE_ADMIN_SDK_KEY`가 없으면 곧바로 ABORT한다(`admin.credential.cert()` 고정). 이 PC에는 `gcloud`가 없고 ADC(Application Default Credentials, 내 Google 로그인을 프로그램이 대신 쓰게 해 주는 파일)도 없으며, `.env.local`에도 그 키가 없다.
- 키 없이 할 수 있는 길은 두 가지다. **둘 다 대표 결정 사항**이다.
  | 안 | 방법 | 비용 |
  |---|---|---|
  | A. ADC | `brew install --cask google-cloud-sdk` → `gcloud auth application-default login`(브라우저 로그인) + 스크립트에 "키가 없으면 `applicationDefault()` + projectId `worldcrown48`" 대체 경로 몇 줄 추가(작은 PR) | 스크립트 수정 = 범위 밖. 키 파일이 아예 생기지 않음 |
  | B. 콘솔 수작업 | Firebase 콘솔에서 `tournaments/chart-preview-eyecheck` · `ranking_cache/chart-preview-eyecheck` 두 문서를 손으로 만든다 | 코드 변경 없음. 단 rankings 배열(5줄 × 필드 11개)을 손으로 넣어야 해서 오타 위험이 큼 |
- **키를 쓸 때의 안전 절차 (안 C, 스크립트 무수정)**
  1. Firebase 콘솔 → 프로젝트 설정 → 서비스 계정 → "새 비공개 키 생성" → JSON 다운로드
  2. 키 내용은 **채팅에 붙이지 않는다.** 터미널에서 `FIREBASE_ADMIN_SDK_KEY="$(cat ~/Downloads/<키파일>.json)" node scripts/seed-chart-preview.mjs`로 넘긴다(클립보드에 복사해 둔 경우엔 `"$(pbpaste)"`)
  3. 눈검사가 끝나면 같은 방식으로 `--clean`을 실행 → 키 JSON 파일 삭제 → 클립보드를 비움(`pbcopy < /dev/null`) → 콘솔에서 **그 키를 폐기(삭제)**
- **권장: 안 C.** 코드 변경이 없고, 키를 한 번 쓰고 바로 폐기하면 노출 창이 수 분으로 줄어든다. 안 A는 반복해서 쓸 일이 생길 때 추가.

### 4-2. ⚠️ 사전 점검에서 찾은 문제 — 시드 대회는 **제목·마감이 빈 채로** 그려질 것
- 시드 대회 문서는 `status: "draft"` · `featured: false` · `hostUid: "seed-chart-preview"`다.
- `firestore.rules` 46–49행을 보면, tournaments 읽기는 `active`이거나 `featured`이거나 **본인이 host일 때만** 허용된다. 시드 대회는 셋 다 아니므로 **누구도 이 문서를 못 읽는다.**
- 차트 페이지(`app/arena/[tournamentId]/ranking/page.tsx` 99행)는 이 문서를 `getDoc`으로 읽어 제목·마감을 채운다. 여기서 권한 거부가 나는데 `.catch`가 없다. 결과는 이렇게 예상된다.
  - 순위·Crown Score는 **그려진다**. `ranking_cache` 읽기 규칙은 `exists()`만 보고, 규칙 안의 exists()는 읽기 권한과 무관하기 때문.
  - **대회 제목 빈칸 · 마감 줄 없음 · 콘솔에 "Uncaught (in promise) FirebaseError: Missing or insufficient permissions" 1건**
- 그래서 이 상태로는 "콘솔 0 · 제목 3언어" 눈검사 항목을 통과할 수 없다. 해결 후보(대표 결정):
  1. 스크립트가 시드 대회를 `status: "active"` · `featured: false`로 심는다. 이러면 피드(`featured == true`만 읽음)에는 여전히 안 오르고 주소로만 열린다. 단 `active` 대회는 크론 집계 창과 Arena 목록 등에 잡힐 수 있어 **확인이 먼저 필요**하다.
  2. 차트 페이지 `getDoc`에 `.catch` 추가 → 콘솔 오류는 사라지지만 제목은 여전히 빈칸.
  - 이 판단은 실제 경로를 걸어 확인한 뒤에 한다. **추측으로 고치지 않는다.**

- **원인 (로컬 dev 서버에서 축약 안 된 오류 원문으로 확인)**: `Text content did not match`. 서버 HTML의 `<style>` 안 CSS가 `[data-active=&quot;true&quot;]`인데, 클라이언트는 `[data-active="true"]`다. React 18이 서버 렌더에서 `<style>{문자열}</style>` 속 **따옴표를 `&quot;`로 이스케이프**하고, 브라우저는 style 내용을 날 텍스트로 읽는다. 그래서 둘이 어긋난다(서버 1353자 vs 클라이언트 1323자 = 따옴표 6개 × 5자)
- **걸리는 곳**: `components/arena/ModuleNav.tsx`(STYLE 속 따옴표 들어간 줄 3) · `components/ranking/RankingView.tsx`(`.rank-help[aria-expanded="true"]` 1줄)
- **영향**: 하이드레이션 실패 → React가 **페이지 전체를 클라이언트 렌더로 다시 그린다**(#423). 화면 결과는 맞게 나오지만, 콘솔 0 기준 불합격 · 첫 화면 깜빡임 · 성능 손해
