## 2. ★ 참가 규칙 v2.1 — 2026-09-06 대표 확정 (재론 금지)

v2.0에서 **게스트(비로그인) 정책만** 바뀐다. 로그인 사용자 규칙은 v2.0 그대로다.

| # | 변경 | 내용 |
|---|---|---|
| 1 | **게스트 한도** | 하루 통틀어 1판 → **하루 통틀어 3판**. 대회는 자유 선택. **대회 수가 늘어도 3판 고정**(MVP1.5 유저 생성 대회가 열려도 안 늘어남) |
| 2 | **게스트 공유** | **개방.** 07-06 HF-2의 "공유 로그인 게이트"를 해제 |
| 3 | **게스트 저장·다운로드** | **잠금 유지.** 공유는 우리 링크를 퍼뜨리는 행위라 열고, 저장은 파일만 가져가는 행위라 잠근다. "간직하려면 로그인"이 유인으로 남는다 |
| 4 | **게스트 공유 링크 UTM** | 로그인 사용자와 **동일 규격** — `utm_medium=share` · `utm_campaign`=대회 슬러그 · `utm_content=crown_card`. 공유 이벤트에 **`is_guest` 파라미터** 신설 |
| 5 | **★ 게스트 표 랭킹 제외** | **게스트가 넣은 표는 랭킹 집계에서 제외한다.** (티오 제안 → 대표 채택) |

### 5번의 근거 (대표 확정 논리)
- 게스트 uid는 **브라우저 창마다 새로 생긴다.** 3판 제한은 사람이 아니라 창에 걸리므로, 시크릿 창을 반복해 열면 한 사람이 무한히 돌 수 있다 — 회원의 "대회당 5판" 천장이 게스트에겐 없다.
- 랭킹에서 빼면 **조작 동기 자체가 사라진다.** 백 번 열어도 랭킹이 안 움직이면 할 이유가 없다.
- **"내 표가 랭킹에 반영되려면 로그인"** 이 새 가입 유인이 된다 — 공유를 열어주며 잃은 유인을 여기서 되찾는다.
- 랭킹 원료 걱정 없음(대표 판단): 공유 카드가 늘어 유입이 늘면 회원 표가 그만큼 늘어난다.

### 3판이라는 숫자
**특별한 근거 없음. "큰 변수가 아니다"는 대표 판단**(2026-09-06). 나중에 조정할 여지가 있는 값으로 다룰 것 — 상수 한 곳에서만 정의한다.

### ⚠️ v2.0 §5 DON'T 2가 뒤집힌다
원 핸드오프는 *"`rankingAggregator` 집계 로직을 건드리지 마라"* 였다. **v2.1의 5번이 이 금지를 해제한다.** 게스트 제외는 집계 로직 변경이다. 핸드오프 §5에 이 사실을 명시할 것.

## 5. 착수 전 실측이 필요한 것 (브레인스토밍 입력)

1. **게스트 표를 어떻게 판별하나** — vote 문서에 게스트 표시가 있는가? 익명 인증 uid를 판별할 수 있는가? 없으면 vote 기록 시 필드를 새로 넣어야 하고, 그건 PR 3이 아니라 PR 2 이전 작업이 된다. **먼저 실측할 것.**
2. **이미 쌓인 게스트 표는 어떻게 하나** — 소급 제외인가, 앞으로만인가. 소급이면 판별 가능한지가 1번에 달려 있다. **대표 결정 사항.**
3. **게스트 3판 한도가 `guest_runs` 문서 구조로 표현되는가** — 현재 `lastRunDate`·`runsToday`·`tournamentId`. tournamentId 필드는 "같은 대회 이어하기 허용" 판정용인데, 3판이 되면 **여러 대회를 오갈 수 있으므로 구조 재검토 필요.**
4. **공유 개방 시 Crown Card 링크가 게스트 uid를 노출하지 않는가** — 공유 URL 형태 확인.
