# DoD 체크리스트 — 킥을 닫기 전

킥마다 §0에 그 킥 고유의 DoD를 쓴다. 이 문서는 **모든 킥에 공통으로 걸리는 항목**이다.
실행 파트너가 항목별로 판정해서 최종 보고에 붙이고, 사람은 ★ 표시된 것만 직접 확인한다.

---

## 1. 코드가 실제로 그 자리에 있는가

- [ ] **커밋 = 푸시** — 로컬에 있는 커밋이 전부 원격에 올라갔다 (`git status` 가 clean, `git log origin/<브랜치>..HEAD` 가 비어 있음)
- [ ] 워킹 트리에 커밋 안 된 변경이 없다 — "고쳤다"고 보고한 것이 커밋에 들어 있다
- [ ] **배포한 SHA = {{MAIN_BRANCH}} HEAD** — 배포가 포함된 킥이면 배포된 리비전을 실제로 확인하고 값을 보고에 적는다

> 옛 코드를 다시 배포하는 사고는 사람 주의력으로 못 막는다. `predeploy-guard` 가 기계로 막지만, 값은 눈으로도 한 번 확인한다.

## 2. 기계 검증

- [ ] `{{TEST_CMD}}` green — **건수를 적는다** (시작 N건 → 현재 M건)
- [ ] `{{GUARD_CMD}}` 위반 0건, 미사용 예외(stale allowlist) 0건
- [ ] `{{BUILD_CMD}}` green
- [ ] 타입 체크 green (해당하는 경우)
- [ ] **새 규칙을 만들었다면 CI에 편입됐다** — 로컬에서만 도는 가드는 다음 주에 죽는다
- [ ] **CI가 "0건 실행하고 green"이 아니다** — 로그에서 실제 실행 건수(`Running N tests`)를 확인했다

> 마지막 항목이 가장 자주 놓치는 함정이다. 조건부 스킵이 걸린 워크플로는 아무것도 안 하고 초록불이 된다.

## 3. 사람 검증 ★

- [ ] ★ 프리뷰에서 **실행 파트너가 지목한 지점**을 눈으로 확인했다
- [ ] ★ 로그인이 필요한 화면은 머지 후 프로덕션에서 30초 확인했다
- [ ] ★ 스모크 테스트 — 실제 데이터로 실제 버튼을 눌렀고, 기대값과 일치했다 (다르면 STOP)

> 프리뷰에서 로그인이 안 되는 건 정상인 경우가 많다(인증 승인 도메인 미등록). 그 자체를 실패로 보고하지 않는다.

## 4. 기록

- [ ] PR 본문 4블록(+E) 작성 — 특히 **B의 실측 수치**와 **D 핸드오프와 달랐던 점**
- [ ] 확정된 결정이 규범 문서(`CLAUDE.md`·용어 문서·스펙)에 반영됐다 — 같은 세션 안에서. 못 하면 **후속 태스크를 즉시 생성**
- [ ] `LESSONS.md` 에 이번에 배운 것 추가 (없으면 "없음"이라고 말한다)
- [ ] 설계 파트너 메모리 갱신 — 완료 상태 · 결정 · 교훈 · 다음 대기열

## 5. 정리

- [ ] 워크트리 제거 (`git worktree remove <경로>`)
- [ ] 브랜치 처리 — 머지 후 삭제, 남긴다면 사유
- [ ] 킥 문서 하단에 완료 표시 (머지 커밋/PR 번호)
- [ ] 임시 파일·디버그 로그·주석 처리한 코드 제거

---

## 판정 양식 (최종 보고에 붙인다)

```
| 항목 | 판정 | 근거 |
|---|---|---|
| 커밋=푸시 | ✅ | git status clean, origin/<브랜치> = HEAD <sha> |
| 테스트 | ✅ | 465 → 479 green |
| 가드 | ✅ | 위반 0건 · stale 예외 0건 |
| 빌드 | ✅ | green |
| CI 실제 실행 | ✅ | Running 12 tests (로그 확인) |
| 사람 검증 | ⏸ | 대표 프리뷰 확인 대기 |
| 문서 동기화 | ✅ | CLAUDE.md v0.2 · 용어 문서 §3 |
| 정리 | ✅ | 워크트리 제거, 브랜치 삭제 |
```

**⏸(대기)를 ✅로 쓰지 않는다.** 사람이 아직 안 본 것은 안 본 것이다.
