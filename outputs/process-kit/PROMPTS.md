# PROMPTS — 실행 파트너에게 붙여넣는 문구 4종

실제로 써서 통한 문구를 자리표시자만 남기고 옮긴 것이다. 그대로 복사해 쓴다.

---

## 1. 착수

킥 문서를 발행한 직후, 실행 파트너의 첫 메시지로 보낸다.

```
{{HANDOFF_DIR}}/KICK_<코드>_<제목>_<날짜>.md 를 읽고 착수해 주세요.
시작 전 git pull.
Auto-STOP 조건을 만나면 멈추고 질문해 주세요.
```

프로세스가 처음이거나 실행 파트너가 킥 방식을 모르는 리포라면 한 줄 더:

```
먼저 outputs/process-kit/README.md 를 정독하세요.
```

**왜 이 세 줄인가**
- 킥 경로 하나만 준다 — 요약해서 넘기면 실행 AI가 원문 대신 요약을 계약서로 삼는다.
- `git pull` — 옛 코드 위에서 작업이 시작되는 사고를 막는다.
- Auto-STOP 한 줄 — **이게 없으면 실행 AI는 막히는 지점을 추측으로 메운다.**

---

## 2. 재개 (응답이 끊겼을 때)

노트북 잠자기·네트워크 오류·API 오류로 응답이 끊기면, 작업물은 이미 커밋되어 있으므로 그대로 이어진다.

```
응답이 끊겼습니다. 이어서 진행해 주세요.
현재 어느 Phase의 어디까지 됐는지 먼저 한 줄로 알려주고 계속하세요.
```

컨텍스트가 날아간 것 같으면(엉뚱한 소리를 하면) 킥부터 다시 읽힌다.

```
{{HANDOFF_DIR}}/KICK_<코드>_<제목>_<날짜>.md 를 다시 읽고,
git log --oneline 으로 지금까지의 커밋을 확인한 뒤 이어서 진행해 주세요.
```

> 30분 넘게 걸릴 작업은 시작 전에 잠자기를 막아둔다 (macOS: 터미널에서 `caffeinate -d`).

---

## 3. STOP 응답

실행 파트너가 멈추고 선택지를 냈을 때. **화면을 캡처해 설계 파트너에게 보이면 선택지 해설과 붙여넣기용 답변을 만들어 준다.**

좋은 답변의 4요소 — **① 번호로 대응 ② 승인/거부 명시 ③ 조건 부가 ④ 이후 계속 지시**

```
① <질문1 번호> → <선택한 안> 승인.
   조건: <근거를 커밋 메시지/PR에 남길 것> · <이것과 다르면 다시 STOP>
② <질문2 번호> → <선택한 안>. <거부한 안>은 하지 마세요.
이후 Phase <X> 계속 진행해 주세요.
```

**빈칸을 못 채우겠을 때** — 추측하게 두지 않는다.

```
그 값은 지금 확정할 수 없습니다. 추측하지 말고,
<대조군 / 최소 버전 / 자리표시자>로 두고 진행한 뒤 보고해 주세요.
```

**실행 파트너의 (권장) 표시는 지금까지 전부 맞았다.** 급할 땐 (권장)을 따라도 안전했다.

> ⚠️ 실행 AI의 대화형 선택 UI에서 Esc를 누르면 "declined"로 닫히지만, **같은 내용을 일반 채팅으로 입력하면 그대로 이어진다.** 막힌 게 아니다.

---

## 4. 마감

사람 검증까지 끝나 머지·배포가 된 뒤.

```
최종 보고를 해주세요.
- PR 4블록(A 무엇을 · B 어떻게 확인했나(실측 수치) · C 판단이 필요했던 것 · D 남긴 것/후속)
- "핸드오프와 달랐던 점" 을 빠짐없이
- DoD_checklist.md 를 항목별로 판정
그리고 워크트리·브랜치를 정리해 주세요.
```

배포까지 실행 파트너가 하는 경우, 배포 후 확인을 명시적으로 시킨다.

```
배포된 SHA가 {{MAIN_BRANCH}} HEAD와 같은지 확인하고 그 값을 보고에 적어 주세요.
```

## 부록 — 하지 말아야 할 프롬프트

| ❌ | 왜 |
|---|---|
| "킥 내용 요약해서 보낼게" | 요약본이 계약서가 된다. 원문 경로를 준다 |
| "알아서 잘 해줘" | Auto-STOP이 죽는다. 멈출 지점이 없으면 추측으로 채운다 |
| "이것도 겸사겸사 고쳐줘" (킥 도중) | 스코프 확장. 다음 킥의 대기열에 적는다 |
| "테스트는 나중에" | 기계 검증이 빠지면 "됐다"를 증명할 수단이 없다 |
| "프로덕션에 바로 올려줘" | 사람 검증 지점을 건너뛴다. 프리뷰 → 눈 → 머지 순서를 지킨다 |
