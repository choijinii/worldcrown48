뉴스룸 승격 — 모듈 분해와 병렬성 지도
2026-08-24 · 전제: 대형 킥 실행 순서(Arena 매치 대수술 → Pitch 쇼케이스 → 뉴스룸 승격 본킥)는 그대로 유지. 이 문서는 뉴스룸을 모듈로 쪼개, 그중 지금 병렬로 미리 진행해도 안전한 조각을 가려내는 지도입니다. 08-09 확정 결정(도메인 격상·창구 多·NewsRail·SiteMapSheet·sitemap/Article schema)과 뉴스데스크 사양(07-22), 미디어 피벗(인터넷신문 등록)을 근거로 작성했습니다.
1"승격"이 뜻하는 것 — 이미 확정된 그림의 재확인
뉴스룸은 지금 "/news 목록 + 기사 페이지 + 사이드 레일"입니다. 승격은 세 겹입니다: ① 지위 — 7도메인 체계의 정식 도메인(라이트 테마 존 — 테마 B안 확정: 매치·투표=다크 / 뉴스룸·정책·계정=화이트)이 되고, GNB(상단 메뉴)와 SiteMapSheet에 정식 자리를 얻는다. ② 화면 — 뉴스룸 홈(피드)·기사 지면이 언론사 수준으로 서고, Around the Pitch(외부 축구 뉴스)와 NewsRail이 결합된다. ③ 발견 — sitemap·Article schema(구글이 기사로 인식하는 구조 데이터)·검색 색인으로 바깥에서 찾아 들어오게 한다. 이것은 인터넷신문 등록(미디어 피벗)의 실체이기도 합니다.
2모듈 분해 9개 — 무엇을 건드리고, 지금 병렬이 되는가
판정 기준은 두 가지입니다: (a) 지금 돌고 있는 PR-2·대기 중인 TOG-1·다음 Arena 킥과 같은 파일을 건드리는가, (b) 대표님의 결정·검토가 얼마나 필요한가.
모듈내용건드리는 곳충돌병렬 판정
N0 기획·규범 스윕 도메인 정의·IA(화면 구조)·"창구 1원칙 폐기" 규범 문서 스윕(08-09 숙제) — 코드 없음, 티오+대표 문서만없음지금 (이 문서가 시작)
N1 뉴스룸 홈 /news를 "목록"에서 "뉴스룸 홈"으로 — 라이트 테마 피드, 헤드라인·최신·카테고리 구획 app/news, components/newsPR-2 ✕ · TOG-1 ✕(그쪽은 admin만)지금 코드 가능 · 1순위
N2 기사 지면 강화 기사 본문 비주얼 블록(스탯 타일·VS 그래픽 — 07-22 지침 ③), 임베드 기사 블록 정비, ✦ AI-Report v2.5 준수 확인 components/news, lib/newsPR-2 ✕지금 코드 가능 · N1과 한 묶음
N3 SEO·색인 sitemap·Article schema·기사 메타(08-13 SEO 신호 확정) + RSS 검토 app/robots·sitemap, 기사 메타(독립 파일 위주)거의 없음지금 코드 가능 · N1 묶음에 동승
N4 콘텐츠 축적 기사 4호~ 발행 리듬(주 2~3건), 주간 랭킹 기사 품질 점검 — 코드 없음, 뉴스데스크 사용 데이터만없음지금 (대표+뉴스데스크)
N5 Around the Pitch 외부 축구 뉴스 피드(thenewsapi — 08-09 "즉시 아님", 실측 미결). 비용·품질 실측 → 붙일지 판단 실측=코드 0 / 구현=components/pitch·news구현은 Pitch 킥과 접점실측만 지금 · 구현은 본킥
N6 NewsRail 정식판 왼쪽+페이지 분할, ≥800px (08-09 확정) — Pitch 화면 구조와 맞물림 components/news/NewsRail + Pitch 배치Pitch 쇼케이스와 얽힘Pitch 킥과 함께
N7 GNB·SiteMapSheet 편입 상단 메뉴·사이트맵에 뉴스룸 정식 항목 — 도메인 지위의 마지막 도장 Navbar·SiteMapSheet (전 화면 공유 파일)공유 파일 — 모든 트랙과 충돌 소지본킥 마지막에 한 번에
N8 뉴스데스크 생산성 콘솔 개선 + 다국어 문구 이관(TOG-1과 같은 파일) components/admin/newsdeskTOG-1과 동일 파일TOG-1에 이어 붙이기
N9 등록·법무 연계 인터넷신문 등록 절차 진행(발행 실적 요건 확인), Search Console 등록 확인(08-13 미결) 행정·콘솔(대표)없음지금 (대표 행정 작업)
병렬 코드의 안전 규칙 2개: ① 동시에 도는 코드 트랙은 PR-2 외에 1개까지만(대표님의 검토·머지 시간이 진짜 병목이므로). ② 번역 사전(messages.ts)은 모든 트랙이 건드리는 유일한 공유 파일이라, 뉴스룸 트랙의 새 문구 키는 몰아서 마지막 커밋으로 넣어 충돌을 최소화합니다.

4시작 전에 정해 주실 것 3가지
질문 1 병렬 코드 1트랙을 "NEWS-1 소킥(N1 홈+N2 지면+N3 SEO)"으로 잡는 데 동의하시나요?
동의하시면 다음 순서로 갑니다 — 우리 절차 그대로: 티오가 뉴스룸 홈 HTML 목업을 먼저 만들어 보여드리고 → 대표 선택·수정 → 소킥 문서 → 승인 → 발행. (PR-2가 끝나기 전에는 목업·킥 문서까지만 준비하고, 코드 착수는 PR-2 머지 후로 하는 안전판도 선택 가능합니다.)
질문 2 기사 이미지 정책(미결)을 이번에 정할까요?
뉴스룸 홈은 썸네일이 있어야 사는 화면인데, "기사 이미지를 무엇으로 쓰나"가 미결로 남아 있습니다. 후보: ⓐ 대회 영상의 유튜브 썸네일 재사용(임베드 법리 안, 추가 작업 적음) ⓑ 스탯 타일 등 자체 제작 그래픽(지침 ③과 일치, 디자인 비용) ⓒ 혼합. 목업에 반영해야 하니 방향만 정해 주세요.
질문 3 N9(행정)를 언제 움직일까요?
Search Console 등록 확인(구글이 우리 기사를 색인하는지 보는 콘솔)과 인터넷신문 등록 절차는 대표님만 할 수 있는 행정 작업입니다. 제가 단계별 안내서를 만들어 드리면 되는데, 지금 병행할지 / 뉴스룸 본킥 때 할지 정해 주세요.
