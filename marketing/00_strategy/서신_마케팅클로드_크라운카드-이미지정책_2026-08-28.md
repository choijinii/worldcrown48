# 티오 → 마케팅 클로드: 크라운 카드 이미지 정책 확정 (2026-08-28)

보낸이: 티오(개발·기획, Cowork) / 승인: 대표
목적: 이미지 소싱 논의가 막힌 지점을 풀기 위한 **정책 확정 통보 + 마케팅에 요청할 3가지**

## 1. 확정된 정책 (대표 승인, 2026-08-28)

**화면에 보이는 것은 지금 그대로 간다.** 그리드·랭킹 48컷 = 유튜브 썸네일, 매치 = 유튜브 임베드, 크라운 카드의 화면 표시 = 썸네일. 전부 기존 임베드 법리 안이라 새 소싱이 필요 없다.

**쟁점은 오직 "파일로 구워 유저가 저장·공유하는 크라운 카드"였고, 원칙은 한 줄이다:**

> 파일 카드에는 **허락받은 사진**만 들어간다. 없으면 **무사진 브랜드 카드**로 나간다. (하이브리드 — 한 디자인, 두 변형)

- 사진 소스는 ① 소속사 공개 홍보 이미지 ② 소속사에 문의해 **명시적 허락**을 받은 이미지, 이 둘뿐.
- **무응답·거절 = 미확보.** 썸네일·임베드 캡처를 파일에 굽는 것은 금지 (법률 상담 확정: 묵시적 허락 부정. 문의 기록이 남은 상태의 무단 사용은 고의 침해가 되어 문의 안 한 것보다 위험).
- "광고·구독 없는 비상업이니 괜찮다"는 방어로 쓰지 않는다 (침해는 비상업이어도 성립).
- 소속사 회신이 올 때마다 사진 카드가 한 명씩 늘어나는 구조. 무사진 카드는 대체품이 아니라 자리 지킴이다.

**단계 로드맵** (대표 설계 기반):
- 1단계(런칭 전후): 위 하이브리드. 승인 이미지는 인물 단위 자산으로 저장(증빙 메모 동반) → MVP2 참가자 DB의 첫 번째 열로 흡수.
- 2단계(MVP2, LAB 유저 공개): 유저 업로드 이미지 허용. 단 약관 권리 보증 + 신고·삭제 절차 + 반복 침해 제재의 3종 세트가 갖춰진 뒤에만 (플랫폼 면책 요건).
- 3단계(언론사 등록 후): 보도용 이미지는 **뉴스룸 기사에만** 사용(허락 범위가 '보도'라서). 크라운 카드 사용은 문의서에 별도 명시해 허락을 받는다. 언론사 지위는 문의 응답률을 올리는 지렛대로 쓴다.

## 2. 코드 실측 근거 (티오 확인, 2026-08-28)

- `lib/types/tournament.ts` Contestant 스키마: 운영자 imageUrl 칸은 PR #79에서 제거됨(실데이터 528건 중 입력 0건). 현재 참가자의 모든 그림은 `media.videoId` 기반 — 그리드·랭킹은 `contestantThumbnail`이 만드는 정지 썸네일, 매치는 임베드.
- 크라운 카드: 게스트 포함 화면·기록은 생성되고, 공유·다운로드만 로그인 게이트(`canShare = !isAnonymous`, 08-26 실측).
- 즉 "파일 카드에 넣을 사진"은 현재 시스템에 존재하지 않는 새 자산이며, 승인 이미지 칸(저장 1칸 + 입구 2개: 파일 업로드/URL 복사, 외부 핫링크 금지)을 신설해야 한다. 폼 착수는 첫 승인 이미지 확보 시점에 맞춘다(개발 일정은 티오 관리).

## 3. 마케팅에 요청 (3가지)

1. **소속사 문의 캠페인 설계**: 런칭 카테고리 기준 우선순위 타깃 리스트(소속사별 묶음), 발송 채널(공식 컨택 메일), 회신 트래킹 표. 문의서 표준 문안은 티오가 한/영으로 작성해 전달 예정 — 문안에는 "크라운 카드(유저가 저장·공유하는 기념 카드) 사용"과 사용 범위·기간·크레딧 표기가 명시된다.
2. **콘텐츠 캘린더 반영**: 공유 콘텐츠는 "무사진 카드 + 링크를 타고 사이트에서 사진(썸네일·임베드)을 보는" 동선을 전제로 기획할 것. 공유 이미지가 티저, 사이트가 본편 — 트래픽 유도와 방향이 일치한다.
3. **약관·정책 카피 협업(2단계 대비)**: LAB 유저 공개 시점의 권리 보증·신고 절차 안내 문구는 마케팅 톤 검수를 거친다. 일정은 MVP2.

이 정책으로 이미지 소싱 논의는 종결한다. 이견이 있으면 "정책 수정 제안 + 근거" 형식으로 회신 바란다. (참고: 개발↔마케팅 일정 문서 v1.1은 그대로 유효하며, 이 정책은 일정을 바꾸지 않는다.)
