# 서신 — 대관 연출(Crown Ceremony) 인계 §8 확인 회신 (개발 티오 → 마케팅)

작성: 티오(개발) / 전달: 대표님 / 날짜: 2026-08-31
회신 대상: 대관 연출 (Crown Ceremony) — 아레나 개편 포함 항목 (2026-08-31)

인계 문서 잘 받았습니다. 결론부터: **대관 연출은 아레나 개편 킥(ARENA-1)에 정식 항목으로 들어갔습니다** — 단독 과제가 아니라 결승 픽 직후 화면으로, 킥 문서에 레이어 7층·타이밍·탭 대기·건너뛰기·모션 최소화 대응까지 그대로 옮겼습니다. 아래는 §8에서 물으신 3가지 확인과, 그 외 개발이 인계 내용을 읽으며 정한 것들입니다.

---

## 1. §8 확인 요청 답변

**① 실제 화면 규격 → 뷰포트 전체(100vw × 100vh). 자산 크기 그대로 진행하시면 됩니다.**
개편 후 매치·결승·대관 화면은 모두 화면 전체를 씁니다. 모바일 세로 390×844 가정은 유효합니다. 데스크톱은 가로가 넓어지는데, 크라운은 "화면의 짧은 변 기준 %"로 배치하므로(예: 크라운 폭 = 가로·세로 중 짧은 쪽의 약 36%) 자산을 다시 계산할 필요가 없습니다. 크라운은 SVG(벡터)라 확대 손실이 없고, 광채 PNG 960px도 데스크톱 최대 표시 ≈ 400px 안쪽이라 3배 여유가 유지됩니다. **제안하신 6종 규격 그대로 OK.**

**② 애니메이션 도구 → 저장소에 없습니다. 새로 들이지 않고 브라우저 내장 기능으로 갑니다.**
실측 결과 framer-motion·GSAP·react-spring 어느 것도 설치돼 있지 않고, 규범 문서도 "CSS transition/keyframes"로 고정돼 있습니다. 대관 연출은 **CSS keyframes + Web Animations API**(브라우저 기본 제공)로 구현합니다. 인계문의 성능 제약(위치·크기·회전·투명도만, 미리 그린 PNG를 회전·확대만)과 정확히 맞고, "도중에 탭하면 마지막 프레임으로" 건너뛰기도 내장 기능 한 줄로 처리됩니다.

**③ crown_main.svg 저장 형태 → 대표님께 드릴 요청 4가지**
(a) 채우기 색을 고정 색값 대신 `currentColor`로 저장 — "대관 순간 금색이 잠깐 밝아지는" 연출을 코드로 하기 위함(인계문 4항과 같은 취지).
(b) 그림자·광채 효과를 SVG 필터로 넣지 않기 — 모바일에서 끊깁니다. 빛은 `crown_glow_back.png` 층이 맡습니다.
(c) 정사각 viewBox(0 0 420 420), 크라운 바닥선이 아래에서 8% 지점에 오도록 — 하강 후 "닿는" 기준선을 코드가 계산하기 위함.
(d) 텍스트·폰트 포함 금지, 패스만.

## 2. 인계 내용 중 개발이 그대로 채택한 것

- **자동 전환 없음 → 정지 프레임 + 사용자 탭 대기**: 규칙(R9)으로 잠갔습니다. 하루 5판 구조에서 두 번째부터 길게 느껴진다는 근거에 동의합니다.
- **정지 프레임 = 완성된 화면**: 사전등록 페이지 캡처 소재로 쓰신다는 점을 완료 기준에 넣었습니다(프리뷰에서 정지 프레임 캡처 1장을 산출물로 냅니다).
- **CROWNED 문구는 폰트**: 이미지 금지 규칙(R10). 3개 언어 키로 들어갑니다 — 문구 자체는 대표님 승인 후 확정.
- **광채는 크라운 뒤, 반짝임은 크라운 앞**: 레이어 순서를 코드 주석에 고정했습니다. `crown_glow_front.png`는 선택 사항 그대로.
- **모션 최소화 설정 → 정지 프레임만**: 대기 시간도 함께 0으로 합니다(움직임만 끄고 3초를 기다리게 하는 실수 방지).
- **크라운 하강 = 빠르게→감속→살짝 튕김**: "이 화면 품질의 대부분이 여기서 갈린다"는 지적을 킥 문서 기술 메모에 그대로 옮겼습니다. 이 곡선은 대표님 콘티 5컷(0.0/0.3/0.8/1.2/정지)을 받아 맞춥니다.

## 3. 개발이 추가한 것 (인계문에 없던 사항)

- **계측 2종 신설**: `ceremony_viewed`(정지 프레임 도달, 모션 최소화 여부 포함) · `ceremony_skipped`(도중 탭, 경과 ms). 이 화면이 "공유가 시작되는 지점"이라면, 얼마나 끝까지 보는지·몇 초에 넘기는지가 크라운 카드 공유율과 함께 읽혀야 합니다. 마케팅 계측 명세(EVENT_SPEC)에 두 줄 추가 부탁드립니다.
- **자산 선행 로드**: 결승 화면에 들어오는 순간 6종을 미리 받아 두어, 픽 직후 대관이 지연 없이 시작됩니다.
- **실패 안전장치**: 자산을 못 받으면 기존 크라운 글리프로 대체하고 연출은 진행합니다(빈 화면 방지).

## 4. 진행 순서 (인계문 9항 기준으로 조정)

1. **티오** — 본 회신(§8 답변) ✅
2. **대표님** — Claude Design에서 대관 연출 콘티 5컷 + 프로토타입, 아울러 스플릿 무대·결승 3분할·라운드 전환·첫 입장 팝업까지 한 번에 설계 → 핸드오프 번들. 이미지 자산 6종 제작(위 ③ 반영).
3. **티오** — 번들과 킥 수치 규칙 대조 → 킥 v1.0 발행 → Claude Code 구현(테스트 3계층) → 프리뷰 눈검증(대표 판정) → 머지.
4. **마케팅** — 정지 프레임 캡처를 사전등록 페이지에 배치, 계측 2종 명세 반영.

한 가지 미리 알려드릴 결정: 아레나 개편은 두 킥으로 나뉩니다. **ARENA-1**(매치 무대 + 대관 연출, W2~3) 뒤에 **ARENA-2**(대회별 대기실·아카이브·브래킷 크기 선택)가 이어집니다. 대관 연출은 앞쪽(ARENA-1)에 있어 일정 영향이 없습니다.
