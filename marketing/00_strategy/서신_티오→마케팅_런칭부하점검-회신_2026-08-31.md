| 1 | 호스팅·DB 등급 | **화면(웹)**: Vercel **Hobby(무료) 플랜** — 2026-08-31 대시보드 실측. Hobby는 약관상 비상업 용도 한정이고 대역폭·함수 한도도 낮아 **런칭 전 Pro(월 $20) 전환이 필수**입니다(대표님 항목, W5 이전 권장). **데이터·투표 처리**: Firebase — Firestore(데이터베이스) + Cloud Functions 2세대(투표 처리 서버), 서울 리전(asia-northeast3). |

| 3 | 상한과 비용 | 인스턴스 1개가 요청 80건을 동시에 처리하므로 **동시 처리 800건**이 투표 서버의 천장입니다. 투표 1건 처리 ≈ 0.2~0.4초 → 계산상 초당 수백~2,000건. 상한을 20·50으로 올리는 건 코드 한 줄 + 배포로 즉시 가능하며, 비용은 쓴 만큼만(1,000명이 47표씩 = 47,000표 ≈ Firestore 쓰기·읽기 합쳐 1달러 미만). **부하보다 요금이 먼저 문제 될 일은 없습니다.** |

## C. 무너질 때의 모습 (가장 중요)

**7. 느려지는가, 안 열리는가 → 느려지고, 그다음 "투표만" 실패합니다. 사이트는 열립니다.**

```
부하 ↑ →  [1단계] 첫 급증 1분: 투표 버튼 응답 1~5초로 느려짐 (서버 깨어나는 중)
        → [2단계] 800건 천장 도달: 일부 투표에 빨간 안내 "투표 실패 / 잠시 후 다시" — 화면은 그대로
        → [3단계] 그래도 페이지·대회 목록·랭킹·기사·크라운 카드 보기는 정상 (다른 경로)
```
"아예 안 열림"이 나는 경우는 부하가 아니라 **결제 문제** 하나뿐입니다: Firebase 결제 계정이 GCP 무료 체험 만료(≈9/10)와 함께 끊기면 투표 서버 전체가 멈춥니다. 이건 대표님이 9/10 전에 결제 계정 활성화로 막아야 하는 항목이고, 이미 일정에 있습니다.

**8. 투표 도중 실패 → 이어서 합니다, 처음부터가 아닙니다.** 대진표와 진행 상황은 저장된 표들로 매번 다시 계산하는 구조라, 새로고침·재접속·다음날 재방문 모두 **마지막으로 성공한 매치 다음부터** 이어집니다. 실패한 그 한 표만 같은 화면에서 다시 누르면 됩니다.

**9. 크라운 카드 생성 실패 → "아직 확정된 Champion이 없어요 · The Arena로" 안내가 뜹니다.** 카드 그림은 유저 브라우저에서 그리므로 서버 부하와 무관하고, 실패 가능한 건 "결승 완료 → 챔피언 확정 기록"을 쓰는 백그라운드 처리가 **밀리는 경우**(부하 시 수 초~수십 초 지연)입니다. 그 사이 위 안내가 보이고, 다시 열면 카드가 나옵니다. 문구가 불친절한 건 인정 — 아레나 개편에서 "카드 준비 중…"으로 바꾸는 것을 포함하겠습니다.

**보너스(마케팅이 알아야 할 것): 1인당 투표 속도 제한이 있습니다 — 분당 20표.** 봇 방어용인데, 열성 팬이 2초에 한 번씩 누르면(분당 30표) "요청이 너무 많습니다" 안내를 보게 됩니다. 서버 부하가 아니라 **가장 열심인 팬이 먼저 막히는** 문제라, 아레나 개편 때 분당 40~60으로 올리는 안을 대표님께 올리겠습니다.

## E. 마케팅 수단에 대한 의견

제안하신 4개 수단 중 **"팬베이스 접촉 시간대 분산"과 "X 게시물 간격 조절"이 우리 구조에 가장 잘 맞습니다** — 병목이 "순간 급증 시 서버 깨어나는 1분"이라, 같은 인원이라도 10분 간격으로 나눠 들어오면 문제가 거의 사라집니다. **토너먼트 4종 순차 공개는 부하 때문이라면 불필요**합니다(대회가 몇 개든 표는 사람 수에 비례하고 대회별 공용 병목이 없음) — 화제성만으로 판단하셔도 됩니다. 사전등록 알림 분할 발송도 부하 관점에선 선택 사항입니다.
