# 메일 주소 운용 정책 (Email Policy)

작성: 마케팅 채팅 / 인계: Cowork / 날짜: 2026-09-04
대상: `worldcrown48.com` Cloudflare Email Routing 주소 9종

---

## 요약

- **주소는 역할별로 나눠 쓴다.** 하나로 다 받으면 나중에 분리할 수 없다
- **공개 주소와 계정 관리 주소를 절대 겹치지 않는다** — 보안 원칙
- **X 계정 개설에는 `accounts@`** 를 쓴다 (비공개 · 서비스 가입 전용)
- **현재 이 주소들은 수신 전용**이다. 발신 설정 여부는 아래 5항 확인 필요

## 1. 주소별 용도

| 주소 | 용도 | 공개 여부 | 주 사용자 |
|---|---|---|---|
| `accounts@` | **각종 서비스 가입·계정 복구** — X, GA4, Vercel, Firebase, Cloudflare 등 | **비공개** | 대표님 |
| `founder@` | 대표 개인 명의 연락 | 필요 시에만 | 대표님 |
| `ceo@` | 대표 명의 공식 서한 — 언론사 등록 신청, 기관 대응 | 필요 시에만 | 대표님 |
| `press@` | **언론 — 보도자료 발신, 기자 문의 수신** | 공개 (기사 하단·보도자료) | 마케팅 |
| `partners@` | **소속사·제휴 — 사진 사용 허락 문의, 협업 제안** | 공개 (문의 메일 발신 주소) | 마케팅 |
| `report@` | 제보·신고 수신 (대회 신고, 부적절 콘텐츠) | 공개 (서비스 내 신고 안내) | 운영 |
| `hello@` | 일반 문의 — 어디에도 안 맞는 모든 연락 | 공개 (X 프로필·사이트 푸터) | 마케팅 |
| `support@` | 사용자 문의 — 버그 신고, 계정 문제, 이의신청 | 공개 (서비스 내 표기) | 개발·운영 |
| `privacy@` | 개인정보·데이터 삭제 요청 | **공개 (법적 필수)** | 개발 |
| `noreply@` | **시스템 자동 발신 전용** — 회신받지 않음 | 노출되지만 안내 안 함 | 개발 |
| 전체 수신 (Catch-All) | 오타·추측 주소 수신 (`info@`, `contact@` 등) | 비공개 | — |

> `accounts@` 는 2026-09-04 신설. 서비스 가입 전용으로 쓰고,
> `founder@` 는 대표 개인 명의 연락으로 역할을 분리했습니다.
> `report@` 의 용도는 위가 제 추정이므로, 다르면 정정 부탁드립니다.

## 2. 왜 나누는가

**나중에 분리할 수 없기 때문입니다.**

전부 `hello@` 하나로 받으면, 나중에 기자 문의만 따로 보거나 소속사 회신만 추리려 해도 방법이 없습니다.
지금 나눠 두면 Gmail에서 **받는 주소 기준으로 라벨을 자동 분류**할 수 있습니다.

그리고 **주소 자체가 신뢰 신호**입니다.
소속사 홍보팀 입장에서 `worldcrown48@gmail.com`에서 온 사진 사용 문의와
`partners@worldcrown48.com`에서 온 문의는 무게가 다릅니다.

## 3. 절대 지킬 원칙 — 공개 주소와 계정 주소 분리

| | 주소 | 이유 |
|---|---|---|
| **계정 관리용** | `accounts@` | 각종 서비스의 **비밀번호 복구 주소**. 노출되면 계정 탈취 시도의 출발점이 됨 |
| **공개용** | `press@` `partners@` `hello@` `support@` `privacy@` `report@` | 스팸·피싱이 오는 것을 전제로 운용 |

**X 계정 개설에 `hello@`나 `press@`를 쓰면 안 되는 이유가 이것입니다.**
공개된 주소가 곧 계정 복구 주소가 되면, 주소만 알면 복구 절차를 시도할 수 있습니다.
X 계정은 런칭 마케팅의 단일 창구라 대체재가 없습니다.

| 서비스 | 사용 주소 |
|---|---|

1인 운영이라 이걸 기억해 줄 사람이 없습니다.

## 5. 확인 필요 — 발신 가능 여부

**Cloudflare Email Routing은 제가 아는 한 수신(전달) 전용입니다.**
`press@` 로 온 메일을 gmail에서 받을 수는 있지만, `press@` **이름으로 보내는 것**은
별도 설정(Gmail의 '다른 주소에서 메일 보내기' + 외부 SMTP 연결 등)이 필요합니다.

이 부분은 **대표님이 이미 준비해 두셨다고 하신 항목**이므로, 제가 다시 판단하지 않습니다.
Cowork에서 아래만 확인해 주십시오.

- [ ] `press@` 이름으로 발신이 실제로 되는가
- [ ] `partners@` 이름으로 발신이 되는가
- [ ] 발신 시 SPF / DKIM 인증이 통과하는가 (스팸함 직행 방지)
- [ ] 회신이 원래 주소(`press@` 등)로 돌아오는가

**소속사 문의 캠페인과 보도자료 배포가 이 두 주소에 걸려 있습니다.**
회신을 기다리는 업무라, 발신이 안 되면 캠페인 자체가 시작되지 않습니다.

## 6. 서비스 내 표기 위치 (개발 반영 대상)

| 위치 | 표기할 주소 |
|---|---|
| 사이트 푸터 — 문의 | `hello@worldcrown48.com` |
| 개인정보처리방침 — 문의처 | `privacy@worldcrown48.com` |
| 이용약관 — 문의처 | `support@worldcrown48.com` |
| 서비스 내 버그·이의신청 | `support@worldcrown48.com` |
| 기사 하단 — 언론 문의 | `press@worldcrown48.com` |
| 서비스 내 신고·제보 | `report@worldcrown48.com` |
| 사전등록 확인 메일 발신자 | `noreply@worldcrown48.com` |
| Firebase 인증 메일 발신자 | `noreply@worldcrown48.com` |

`privacy@` 표기는 개인정보 관련 법령상 **문의 창구를 명시해야 하므로 필수**입니다.
다만 구체적 요건은 제가 법률 판단을 할 수 없으니, 표기 자체는 반드시 두고
문구는 약관 검토 시 확인이 필요합니다.

## 7. Gmail 수신함 정리 방법 (대표님)

전부 `worldcrown48@gmail.com` 으로 모이므로, 라벨을 나눠 두지 않으면 뒤섞입니다.

Gmail 필터를 아래처럼 만드시면 됩니다.

| 조건 (받는사람) | 라벨 |
|---|---|
| `press@worldcrown48.com` | 📰 언론 |
| `partners@worldcrown48.com` | 🤝 소속사·제휴 |
| `support@worldcrown48.com` | 🛠 사용자문의 |
| `privacy@worldcrown48.com` | 🔒 개인정보 |
| `hello@worldcrown48.com` | ✉️ 일반 |
| `accounts@worldcrown48.com` | 🔑 계정 |
| `report@worldcrown48.com` | 🚩 제보·신고 |

**`partners@` 라벨은 특히 중요합니다.** 소속사 회신은 언제 올지 모르고,
놓치면 사진 사용 허락 하나가 그대로 날아갑니다.
이 라벨만 별도 알림을 켜 두시는 것도 방법입니다.
